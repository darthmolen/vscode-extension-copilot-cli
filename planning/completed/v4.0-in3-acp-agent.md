## B. What IN-3 actually delivered

Ten ACP methods — `initialize`, `session/new`, `load`, `prompt`, `cancel`, `close`, `set_mode`,
`list`, `fork`, `delete` — with permission forwarding, streamed messages, reasoning, tool calls,
**file diffs**, **plan entries**, usage and errors, plus sub-agent traffic tagged in `_meta` so a
generic host renders it inline and our dock can still route it.

8 files in `src/acp/`, 22 ACP test files, 2119 tests passing.

**Verified three ways, deliberately**: 36/36 through our own NDJSON harness against a real CLI; then
**Zed**, a third-party editor whose reading of the protocol owes nothing to ours; then two bugs found
by neither, described below.

### What the second consumer found

The strongest argument for this work turned out not to be distribution. An independent consumer of
`SDKSessionManager`, `SessionService` and `CopilotClientProvider` found defects the sidebar could
not:

- **`ModelCapabilitiesService` was never initialised whenever the client provider was injected** —
  degrading model fallback, vision support and attachment validation, silently, for a whole agent
  process. The fix moved initialisation into the manager that owns the service and deleted the
  provider hook, which had been a second writer for the same fact.
- **`session/list` offered plan halves as conversations** — 197 of 909 — which is the same fact P4
  exists to fix, surfaced from the opposite direction.
- **A racy test of my own**, which awaited `notify()` — a notification resolves when *sent*, not when
  *handled* — and had been passing by luck.

## C. What changed underneath v4.0

Three things learned this week that the original plan did not know. All three narrow it.

### 1. The two halves have different risk owners

The ACP agent pays off through **any** ACP host and we control all of it. The AHP client pays off
only through an AHP host, which is Microsoft's to grant, and OUT-1 has been silent for a week.
Scoping them as one release makes the half we control wait on the half we do not.

**Proposed:** v4.0 narrows to the AHP client half (IN-4, IN-6, IN-9). Cross-talk thread 02 carries
the question to Lane B, who own the release train. **Open.**

### 2. Publishing the agent is not the value

`copilot --acp` is **already in the ACP Registry** as `@github/copilot@1.0.80`, auto-bumping hourly
against our hand-bumped 1.0.68. Measured side by side, upstream advertises `authMethods` we lack
entirely, `image` and `embeddedContext` prompt capabilities where ours are `false`, MCP
capabilities, and three session modes to our two.

We lead on `session/fork`, `session/close`, `usage_update`, and two deliberate security choices — a
permission prompt titled by the **command** rather than the model's `intention`, and honouring
`canOfferSessionApproval` where upstream offers a session-wide grant anyway.

Their plan mode is **one session**; ours is two, so context isolation is real — and is the same
decision that produced the 197 plan halves. **The differentiator and the debt are one thing.**

Evidence: `planning/spikes/acp-comparison/FINDINGS.md`. Consequence:
`planning/in-progress/v3.15.0-acp-release.md` is **marked falsified**; its §4 survives.

### 3. The CLI cannot carry work↔plan pairing

Spiked for Lane B's P4: the CLI honours `detachedFromSpawningParentSessionId` by writing a
`.detached` marker and then **discards the parent id**, and the `sessions.*` surface has no mutate
path. So it is a hide-me boolean whose argument is thrown away, and the ~200 plan halves already on
disk can never be flagged. Approach 1 as designed.

Evidence: `planning/spikes/detached-sessions/FINDINGS.md`.

## 3. Facts that cost real time — do not re-derive

1. **Never pass a method name as a string literal — use `acp.methods`.** `notify()` has an
   escape-hatch overload: a typo'd string **compiles clean** under `tsc --strict`. A typo on the
   constant is `TS2551`.
2. **`initialize` is not guaranteed to run.** `buildSession().start()` issues `session/new` alone.
   Handlers must work uninitialised. Default deny; let `initialize` *upgrade*.
   **Correction (2026-08-19): capabilities do NOT gate permission forwarding.** Earlier revisions of
   this doc, of the ticket and of the Lane B addendum all said they did. Verified twice against
   `research/acp-sdk/src/`: `ClientCapabilities` (`schema/types.gen.ts:4462`) has `fs`, `terminal`,
   `session`, `plan`, `auth`, `elicitation`, `nes`, `positionEncodings` and nothing
   permission-shaped; and on the `Client` interface (`acp.ts:3740`) `requestPermission` is one of
   only **two non-optional members**, while every capability-gated method is declared `?`.
   `session/request_permission` is baseline protocol surface, so **forwarding is unconditional**.
   `DENY_ALL_CLIENT_CAPABILITIES` and `upgradeCapabilities` stay as they are — they correctly gate
   `fs`/`terminal`. The underlying worry is real but relocates: the failure is "we could not ask, so
   we approved", and the fix is the deny fallback, not a capability branch. Two tests guard it — a
   permission with no `initialize` at all, and one after an `initialize` advertising nothing.
3. **`session/cancel` is NOT free.** The prompt handler receives a `signal`, but **verified: a
   cancel notification does not abort it.** With no `onNotification` handler the cancel is silently
   dropped and the turn returns `end_turn`. Model it fire-and-forget — a notification has no reply,
   so throwing becomes an unhandled rejection rather than a client-visible error.
4. **The handler context is `{ params, requestId, signal, client }`** — not `context`.
5. **The client drives:** `clientApp.connect(agentApp)`.
6. **ESM/CJS is settled.** The SDK is ESM; we compile to CJS; `module: Node16` preserves
   `await import()`. The agent is its own process and never enters the extension bundle.
7. **ACP multiplexes** — every request carries `sessionId`.
8. **The SDK fills schema defaults before handlers run** (verified for omitted, `{}` and partial),
   which is why `upgradeCapabilities` is a plain assignment. Two tests pin that as an *SDK contract*
   and say so.

### Process lessons

**Read the source, not the `.d.ts`.** Three consecutive wrong API guesses came from type
declarations; what worked was dumping the live object:

```js
const keys = o => [...new Set([...Object.keys(o), ...Object.getOwnPropertyNames(Object.getPrototypeOf(o) || {})])];
```

**Mutation-test every claim.** It repeatedly found tests passing for the wrong reason — a capability

**Check claims before repeating them.** Two assertions in this work turned out false on inspection —

## 4. Permissions (scope item 4) — **done**

`SDKSessionManager` no longer hardcodes `onPermissionRequest: approveAll`. An ACP agent forwards to
`session/request_permission`; the extension is unchanged.

```
Copilot SDK ──PermissionRequest──▶ SDKSessionManager.permissionHandler
                                     └─▶ SdkSessionBackend  (translates both directions)
                                           └─▶ CopilotAcpAgent requester
                                                 └─▶ client.request(session/request_permission)
```

**The finding that decided the whole shape.** `getSessionHooks()` installed an `onPreToolUse` hook
returning `{ permissionDecision: 'allow' }` at all twelve session-creation sites, and a spike against
the real CLI showed that with it in place **the CLI emits no `permission.requested` event at all** —
so the feature was dead on arrival and no amount of correct mapping would have helped. The remedy
this doc previously proposed, returning `'ask'`, is also wrong: it restores a request but downgrades
it to the generic `hook` variant carrying only `toolName` and a JSON blob, losing `fullCommandText`,
`commands[]`, `intention` and `canOfferSessionApproval`. Returning `{}` keeps the hook's actual
reason for existing (file snapshots) and lets the native `shell`/`write` request through intact.
Evidence: `planning/spikes/acp-agent/spike-permission-hook.mjs`, five cases, recorded in that
directory's `FINDINGS.md`.

**Decisions taken.**

| Question | Decision |
| --- | --- |
| Cannot reach the client (none connected, request throws, times out) | **Deny** — the SDK's own `{ kind: 'user-not-available' }`. Never approve. |
| Options offered | `allow_once`, `allow_always`, `reject_once`, with per-variant `approve-for-session` payloads. |
| `reject_always` | **Not offered.** Copilot's decision union has no session-scoped reject; offering one would be a button we cannot honour. |
| Unattended escape hatch | `yolo` flips the **fallback only**. A host that answers is still obeyed, including when it says no. |
| ACP `title` | The action being **authorised** — the command, the file, the URL. Not `intention`: that is model-authored prose, and it would let a prompt read "Tidy up harmlessly" over an `rm -rf`. `intention` still reaches the host verbatim in `rawInput`. |
| Waiting | Bounded at ten minutes. The SDK dispatches permissions fire-and-forget, so an unanswered request would leave the tool call pending for the life of the session. |

**Where the deny lives.** In exactly one place — `SdkSessionBackend`. The agent does not answer for a
missing client; it declines to install a requester and lets the backend's fallback stand. A second
answer in a second file is a disagreement waiting to happen.

**Files.** `src/acp/permissionMapper.ts` (new, pure), `SdkSessionBackend.ts` (translator + policy),
`CopilotAcpAgent.ts` (`onConnect`-scoped requester, re-pointed on reconnect), `createAcpAgent.ts`
(`yolo` → fallback), `sdkSessionManager.ts` (`setPermissionHandler`, hook fix).

**Verified:** 17/17 through the wire against a real CLI, including a real `shell` permission
forwarded and answered — `"Run: echo …"` with two options, `allow_always` correctly withheld because
`canOfferSessionApproval` was false.

**One latent bug found on the way.** The module-level `approveAll` was `undefined` until `loadSDK()`
ran, and `client.ts` derives the wire flag `requestPermission` from `!!config.onPermissionRequest` —
so any config built before the SDK finished loading told the CLI that nobody would answer, and a
request under that flag hangs pending forever. The default is now seeded at declaration.

## 4c. The 2026-08-19 audit — five closed, two deferred

Found by auditing the shipped agent against the ACP method surface and the ticket's own scope, not
by a test failing. Closed 2026-08-21.

### 1. `session/load` replays — **done**

It ignored `replayFrom` and returned modes, so a host showed an empty transcript while
`events.jsonl` held the conversation. It now sends the stored turns as `session/update`
notifications *during* the request, then answers — the mechanism the SDK's own server test
describes. Each turn is attributed with `user_message_chunk` or `agent_message_chunk`: replaying a
user's words as agent output would render the assistant talking to itself.

Reading history is allowed to fail without failing the load. The transcript is worth less than the
session. The reader reuses `SessionService.loadSessionHistory` rather than parsing `events.jsonl`
again — a second parser is a second opinion about which events count as "what was said", and the
ACP transcript and the sidebar transcript would disagree the first time the CLI added an event type.

### 2. `session/close` — **done**

Cancel, then release, then forget — in that order, because freeing a manager mid-turn pulls the CLI
session out from under running work. The session is dropped from the map **unconditionally**,
including when teardown throws: a backend that failed to shut down has still stopped being usable,
and keeping it addressable would reintroduce the leak the method exists to prevent.

### 3. `stopReason` — **done for `cancelled`**

The race is the normal case, not the edge one: `sendMessage()` resolves when the SDK goes idle, and
aborting is exactly what makes it go idle. So a cancelled turn resolves *successfully*, and reading
the outcome off whether the call threw reports `end_turn` every time. Hence a flag, cleared per
turn — a cancel belongs to the turn that was running, and a later prompt is a new intention.

`max_tokens`, `max_turn_requests` and `refusal` are still **not claimed**. The manager surfaces no
signal for them, and returning one we cannot detect is the same lie in a different costume.

### 4. `onDidProduceDiff` → ACP diff content — **done**

The costly omission: ACP has a first-class diff content type, so the entire inline-diff experience
was invisible over the protocol. The mismatch was real — our event carries a pair of **paths**
(VS Code's diff editor takes URIs), ACP wants **text**, because a host at the far end of a pipe
cannot read our filesystem.

The two absences mean opposite things and are handled separately: no snapshot means the file did not
exist before (`oldText: null`, ACP's documented "None for new files", which is what lets a host
render *new file* rather than *every line deleted and re-added*); no **current** file means there is
nothing truthful to show, so nothing is sent. Read synchronously inside the emitter callback so a
diff cannot overtake the tool update it belongs to.

### 5. `plan_update` — **done**, and this is where the lesson is

`planUpdate` had a green unit test and **no caller**. Plan mode worked end to end while a host was
never told the plan changed, and nothing failed — because a unit test on a pure mapper proves the
shape and says **nothing** about the wiring. It survived a whole session of mutation testing,
because mutation testing only ever examined code that had a caller.

The signal is `session.todos_changed`, and it carries nothing: *"No payload — clients should call
`readSqlTodosWithDependencies()` to fetch the current state."* So the manager fetches and publishes
the result rather than the bare signal, or every consumer repeats the RPC and gets a different answer
depending on when it ran. Note it is **`todos_changed`, not `plan_changed`** — the latter reports
that the prose `plan.md` file was created/updated/deleted, while ACP's `PlanEntry` is a checklist.

Two mismatches the mapper absorbs, both recorded because both are judgement calls a later reader
would otherwise mistake for data:

- **ACP requires `priority`; the todo table has no such column.** Every entry gets the same value.
  Deriving a spread from wording or position would make the plan look ranked by something the source
  never expressed, and a reader would believe it.
- **ACP's `status` is a closed set; the CLI's is free text.** Unknown values map to `pending` — the
  safe unknown, true of anything we cannot classify, where guessing `completed` ticks a box nobody
  ticked.

Dependency edges are kept in `_meta`. The call is literally `readSqlTodosWithDependencies`; asking
for the edges and discarding them would throw away the only record of which step waits on which.

**Tested at every link** — manager signal, backend event, mapper shape, notification at a real
client. The first attempt still missed the manager→backend link, and a mutation caught that too.

`onDidReceiveReasoning` have no obvious ACP variant; that is a decision to make explicitly rather
than leave them looking forgotten.

### What the wire gate covers now

**26/26.** The old 17/17 never asked to load a session with history, close one, or see a diff or a
plan — which is why an audit found those gaps and three green suite runs did not. It now asks for
all four. The plan assertion is **conditional**: whether the model reaches for its todo tool is a
model decision, so requiring a plan would fail the gate for a reason that says nothing about our
mapping — but the shape of one that does arrive is entirely ours, so it is checked rather than
printed.

## 7. Repo rules that bite here

- **The suite is flaky.** A single red run proves nothing; **a single green run proves nothing
  either.** Re-run a failing file alone — and **not in the same breath as a full suite**, which can
  itself produce a false failure.
- **Squash-merge breaks ancestry checks.** `git merge-base --is-ancestor` false-negatives on
  anything squash-merged. Verify by **content** (`git diff --stat origin/main <sha>`).
- **`gh pr edit` is broken here** — it queries deprecated `projectCards` and **silently aborts**.
  Use `gh api -X PATCH repos/.../pulls/N -F body=@file`.
- **Never `git add -A`** — the sibling lane's untracked files land in your commit.
- **Commit messages with backticks need `-F file`**, not `-m`; bash expands them and silently blanks
  the text.
