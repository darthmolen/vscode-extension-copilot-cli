## What v5.0 is now

VS Code runs agents in a dedicated **Agent Host** speaking **AHP**, with **ACP**
as the documented host-facing adapter interface. That draws a seam through our
architecture exactly where our sub-agent dock already sits:

```text
our extension (AHP client + VS Code integration)  ──AHP──▶  host  ──ACP──▶  our agent ──▶ Copilot SDK
```

Today we are harness *and* client in one process, joined by a bespoke 66-message
RPC. v5.0 splits those halves along the protocol seam.

## Resolving the two competing v5.0 definitions

The roadmap carried two:

- **Event architecture transition** (typed event bus, replacing ~180 lines of
  manual wiring in `extension.ts`) — **absorbed**. It is the decoupling this
  needs, and Phase 0.1 already delivered its first slice.
- **ACP migration** on the dead branch — **superseded**. Its design was *replace
  the SDK with an ACP client against `copilot --acp`*, which is blocked by
  cli#1574 (custom tools ignored) and cli#1607 (no session-level tool
  permissions). Its original trigger — the belief that `--headless` had been
  removed — was disproven.

**The reframed direction keeps the SDK and exposes ACP outward.** `copilot --acp`
is never invoked, so neither blocker applies. Phase 0.2 proved it live.

## Design constraint carried forward

**The dock stays a depth view; the Agents window is the breadth view.** They are
complementary surfaces the user switches between, not competitors. Do not grow
the dock into a session browser, and do not feature-match the Agents window.
