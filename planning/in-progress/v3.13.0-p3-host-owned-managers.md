# v3.13.0 P3 — Host-owned managers

**Status:** written 2026-08-19, not started. Sequenced **before** the work↔plan pairing design,
because pairing wants to hang state off hosts that this task moves.

**Companion reading:** [`v3.13.0-chat-in-a-tab-checkpoint.md`](v3.13.0-chat-in-a-tab-checkpoint.md)
§7.4–§7.8 — the three live passes that made this urgent rather than tidy.

---

## 1. Why now

Task 7 shipped a second surface. The module-level `sessionManager` in `extension.ts` was *"the
window's session"* while there was one surface; it is now **"whichever session started last"**, and
three live defects have already come out of that:

| Found | Symptom | Status |
| --- | --- | --- |
| §7.4 | New Tab mirrored the sidebar — one session, two surfaces | fixed, but by removing a second decision site, not the cause |
| §7.7 | Two concurrent starts clobbered the shared handle; both hosts adopted one id, one CLI session orphaned | fixed by returning the manager instead of reading the slot |
| §7.7 | **The tab's dropdown and New Session drive the sidebar** | **not fixed — this task** |

The first two were patched at the seams. The third cannot be, because the seam *is* the global.

**Measured, not estimated.** Five RPC handlers have `ctx.sessionHost` in scope and throw it away,
dispatching a window-scoped command instead: `onSwitchSession`, `onNewSession`, `onTogglePlanMode`,
`onAcceptPlan`, `onRejectPlan` (`registerChatHandlers.ts:154, 159, 174, 183, 188`). Behind them,
**34 lines in `extension.ts` touch the global**.

## 2. What the global provides today: nothing window-scoped

Every read, classified. There is exactly one bucket.

| Reads | What they actually want |
| --- | --- |
| `enablePlanMode`, `disablePlanMode`, `acceptPlan`, `rejectPlan`, `getPlanFilePath` | the session the user is looking at |
| `listMcpServers`, `listConfiguredMcpServers`, `getAvailableModels`, `validateAttachments` | the session the surface belongs to |
| `stop()` in new-session / switch-session / stop-chat, the fork handler | that session |
| the `isRunning()` guards | *"is mine running"* — the question C2 proved it cannot answer |
| `dispose()` in `deactivate` | **all** of them, which it does not do |

Not one is *"a thing this window has, once"*. `deactivate` looks window-scoped and is the opposite:
it disposes a single manager, so every other host's leaks — a leak that already exists on session
switch and gets one worse per tab.

**The genuinely window-scoped thing already has a home and is wired wrong.**
`CopilotClientProvider` owns the CLI process. Its own header says it *"lets N `SDKSessionManager`s
share one CLI process: a manager given a provider consumes it, while a manager that builds its own
owns it."* `SDKSessionManager` carries `ownsClientProvider` and guards `stop()` with it. The seam is
complete — and the single construction site passes six arguments where the provider is the seventh,
so **it has never been shared**. Every manager spawns its own CLI.

## 3. Target shape

```
window   CopilotClientProvider   one CLI process    [today: N, never shared]
         ModelCapabilitiesService  one model catalogue  [today: one per manager]
  host   SDKSessionManager       one session, owned and disposed by its host
           workSession  live  →  the host's surface
           planSession  live  →  no host, no surface  (unchanged; see §8)
```

The module-level `sessionManager` is deleted. Not deprecated — deleted, so "reads the wrong session"
stops being expressible.

## 4. Design

### 4.1 The host's command surface grows to cover what the global answered

`ChatSessionHost` already exposes `prompt · cancel · switchModel · compact · rename · selectAgent ·
reloadAgents`, all routed through the `#private` manager. The additions are the same shape:

```ts
enablePlanMode(): Promise<void>
disablePlanMode(): Promise<void>
acceptPlan(): Promise<void>
rejectPlan(): Promise<void>
stop(): Promise<void>
planFilePath(): string | null
availableModels(): Promise<any[]>
validateAttachments(paths: string[]): Promise<{ valid: boolean; error?: string }>
listMcpServers(): Promise<any[]>
listConfiguredMcpServers(): Promise<Record<string, any>>
```

`any[]` rather than `ModelInfo[]` / `McpServer[]` on purpose, matching how `SessionManagerLike`
already declares `compactSession(): Promise<any>`. `ChatSessionHost` is free of `vscode` and SDK
imports so it stays requirable from plain mocha and portable to v4.0; importing SDK types for these
signatures would spend that for decoration.

`.manager` stays `#private`. Task 5 rerouted 75 call sites specifically so v4.0 can swap the manager
for an AHP session handle; these ten must not be the exception that undoes it.

**`SessionManagerLike` grows to match.** It is the declared slice, and the point of declaring a slice
is that it states everything we touch.

### 4.2 The five handlers route through the surface's host

```ts
// before
ctx.reg(ctx.rpcRouter.onAcceptPlan(() => {
    vscode.commands.executeCommand('copilot-cli-extension.acceptPlan');
}));

// after
ctx.reg(ctx.rpcRouter.onAcceptPlan(async () => {
    await ctx.sessionHost?.acceptPlan();
}));
```

This is the whole of defect C. `switchSession` and `newSession` are the two with real logic behind
them and are covered in §4.3.

### 4.3 Commands keep working, and learn who they are for

The palette entries stay — they are contributed UI. Each takes an optional host and resolves one when
it is not given:

```ts
function commandTarget(): ChatSessionHost {
    // The chat tab the user is actually looking at, else the sidebar. A panel
    // knows whether it is the active tab; the sidebar is the standing default.
    return chatPanels.activeHost() ?? sidebarHost;
}
```

Defaulting straight to the sidebar would be wrong in the common case — palette invoked *from* a chat
tab — so the active-panel check is part of this task, not a follow-up.

`handleNewSession(host)` and `handleSwitchSession(host, sessionId)` then operate on that host: stop
**its** manager, clear **its** surface, start into **it**. Today they stop the global and clear
`sidebarSurface` unconditionally, which is exactly what the live run showed.

### 4.4 Manager lifetime moves to the host

- `ChatSessionHost.dispose()` disposes its manager. `detachManager()` keeps its current meaning
  (drop the subscriptions, keep the manager) so a session switch still works.
- `ChatSessionRegistry.disposeAll()` therefore reaches every manager, and `deactivate` stops calling
  `sessionManager.dispose()` on one.
- **`wireManagerEvents` stops pushing into `context.subscriptions`.** It registers roughly ten
  window-scoped handlers per manager into extension-lifetime storage, so today every session switch
  leaks a set and every tab adds one. They belong to the host that owns the manager.

### 4.5 One CLI process

Build one `CopilotClientProvider` at the composition root and pass it as the seventh argument. Two
things have to move with it, and both are genuinely window-scoped:

- **`ModelCapabilitiesService`.** It is the provider's `onClientStarted` hook and it is a *model
  catalogue* — the available models do not differ per session. One instance, injected.
- **Stopping it.** With an injected provider `ownsClientProvider` is false everywhere, so nobody
  stops the CLI. `deactivate` must, after the registry has disposed its hosts.

`useYolo` and `workingDirectory` already read window-wide config and the workspace folder, so they
need no change.

> **Verify before relying on it.** The sharing path has never executed. Per CLAUDE.md's SDK-first
> rule this gets a spike in `planning/spikes/shared-client/` — two managers, one provider, two live
> sessions — before the extension depends on it. If the spike fails, §4.5 drops out and the rest of
> this task still lands; N processes is a cost, not a correctness problem.

### 4.6 What stays window-scoped

`WorkspaceRuntimeState` (already), the status bar, `SubagentPanelService`, the MCP registry and
config service, `CliBundleService` / `CliCapabilityService`, and the two above. Everything else is a
session's.

## 5. Sequencing

Each commit green before the next; the live-breaking one is first so it can be verified early.

1. **The five handlers + the host verbs they need.** Defect C dies here. No lifetime changes.
   Verifiable live on its own: the tab's dropdown and New Session act on the tab.
2. **`handleNewSession` / `handleSwitchSession` / `handleStopChat` / fork take a host**, and
   `commandTarget()` resolves the active panel.
3. **Delete the global.** Everything left — MCP providers, `viewPlanFile`, `validateAttachments`,
   `getAvailableModels` — reads its host. `let sessionManager` is removed, not emptied.
4. **Manager lifetime to the host**, `wireManagerEvents` subscriptions with it, `deactivate` through
   the registry.
5. **Spike the shared provider**, then wire it if the spike holds.

## 6. Testing

The seams are already `vscode`-free, so most of this is plain mocha:

- **Host verbs** — each forwards to its own manager and no other; each is a no-op with a clear
  message when the host is not live. Two hosts, one command, assert the other did not move.
- **`commandTarget()`** — active panel wins; sidebar when none; sidebar when the active tab is not
  a chat tab.
- **`handleNewSession` / `handleSwitchSession`** — the *target* host's manager stops and restarts;
  a bystander host's does not. This is the live defect, as a test.
- **Lifetime** — `registry.disposeAll()` disposes every manager including a host that never got a
  session id; `wireManagerEvents` subscriptions die with their host.
- **Shared provider** — the spike first, then: two managers over one provider, and stopping one does
  not stop the other's CLI (`ownsClientProvider` already encodes this; it has just never run).

**Live**, and these are the ones that matter because every defect so far surfaced here and not in the
suite: the tab's dropdown switches the *tab*; New Session in the tab makes a new session *in the tab*;
plan mode entered in the sidebar and accepted in the sidebar while a tab is open; `ps` for copilot
node processes before and after §4.5.

## 7. Risks

- **Plan mode is the sharpest edge.** `acceptPlan` currently no-ops silently when `currentMode !==
  'plan'`, which is how the wrong-session bug hides. Routing it to the right host fixes the routing;
  the silent return should become a visible message either way.
- **`handleForkSession`** takes the manager directly (`const manager = sessionManager`). It needs the
  host, and fork is Task 10's subject — keep the change mechanical here.
- **Deleting the global is a wide diff.** 34 lines, most one-for-one. The risk is a missed
  `!sessionManager` guard becoming an unguarded host call; every new host verb therefore states its
  own not-live behaviour rather than relying on the caller.
- **The shared provider is unproven.** Gated behind a spike (§4.5).

## 8. Out of scope

- **Plan sessions still get no host.** Unchanged invariant; the work↔plan pairing design depends on
  resolving that relationship *off disk* precisely because the plan half is hostless.
- **The work↔plan pairing itself** — its own spec, after this.
- **Entry points** (the `editor/title` widget), **Task 9** (recording a deliberate session choice)
  and **Task 10** (fork in a tab) are unaffected and unmoved.
- **The double transcript read** on tab restore (§7.8) — removable once this lands, not before.
